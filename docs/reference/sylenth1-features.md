# Sylenth1 feature inventory (Part 1 target)

Source: *Sylenth1 User Manual*, version 2.5 (© 2015 LennarDigital). Page numbers are the manual's printed page numbers. Everything here is written in our own words and describes **behavior only**.

Where the manual leaves out a detail (exact ranges, curve shapes, and list contents), it is marked **Unspecified**. Settle those by listening to and measuring the real plugin, or by watching the [overview video](https://www.youtube.com/watch?v=y3wMVOdIZ1c). Record each decision in the matching component doc.

Features added after the manual (v3.x) are listed in [§15](#15-additions-after-manual-v25-from-the-v3x-changelog). They come from the official changelog.

## 1. Architecture and signal flow (pp. 8–9)

- Two **parts**, A and B. Each part has 2 oscillators, 1 filter, and 1 amplitude envelope.
- The two oscillators in a part are summed and sent to a filter. Using **input select**, either filter can take its own part, both parts (AB), or nothing (`--`); the other part alone is apparently not offered (V1). See [Voice structure and routing](#voice-structure-and-routing).
- Filter → amp envelope → **mixer** (Mix A, Mix B) → **master effects** → main volume → output.
- The **Filter Control** panel controls filters A and B together. It is not a third filter.
- Everything up to the mixer is per voice (polyphonic). The master effects are global.
- Parts that are not in use are switched off automatically to save CPU (p. 6).
- **Part select** chooses which part the UI shows. **Solo** plays only the selected part (manual pp. 9–10), and follows Part select while it is on (MusicRadar). What it silences on a crossing part, how it switches, and whether it is a parameter: [Part solo and skipping unused parts](#part-solo-and-skipping-unused-parts) (PS1–PS5; M1.4 task 5).

## 2. Oscillators (pp. 5, 14–15)

Four oscillators: A1, A2, B1, B2.

| Control | Behavior |
|---|---|
| Voices | 0–8 unison voices. 0 turns the oscillator off. See [Unison](#unison). |
| Waveform | 8 waveforms "emulating common analog wave shapes" (p. 14). **The manual does not name them.** Third-party sources do: see [Waveforms](#waveforms) below. |
| Octave / Note | Coarse tuning. Centered by default (0). Octave −3 to +3, Note −7 to +7 semitones, in whole steps (see [Tuning, volume, pan, and invert](#tuning-volume-pan-and-invert)). |
| Fine | ±1 semitone, continuous; default 0. |
| Volume | Oscillator output level. Knob 0–10; taper unspecified. |
| Phase | 0–360° start phase. Only has an effect when Retrigger is on. See [Phase and Retrig](#phase-and-retrig). |
| Detune | Spreads the pitch of the unison voices around the center pitch, as in a supersaw. Law: see [Unison](#unison). |
| Stereo | Spreads unison voices across the stereo field: 0 is mono, 10 is full width. Needs more than 1 voice. Law: see [Unison](#unison). |
| Pan | Oscillator pan, 0 (left) to 10 (right), centred by default (pp. 10, 15). Law unspecified. |
| Retrig | Restarts every voice at Phase on each note-on. Off: free-running (see [Phase and Retrig](#phase-and-retrig)). |
| Inv | Inverts the output, for PWM-style tricks. |
| C / P | Copy and paste oscillator settings, including between presets. |

Requirements: alias-free; stable from below 0.01 Hz up to Nyquist; up to 32 voices per note (4 oscillators × 8 unison voices) and 512 voices in total.

**Range** ([oscillator-range.md](../dsp/oscillator-range.md)). The oscillator takes any pitch as a fractional note, so 0.01 Hz (note −115.79 at A4 = 440 Hz) and below arrive through modulation, bend, and master tune. What happens above Nyquist is our decision, not a measured behaviour: no source says what Sylenth1 plays there.

### Phase and Retrig

The manual gives only the outline: Phase is a 0–360° start phase that only has an effect when Retrig is on, and Retrig restarts every voice at Phase on each note-on (pp. 14–15). M1.1 builds the rest as below ([oscillator-phase.md](../dsp/oscillator-phase.md)).

|---|---|---|---|

| Retrig on, from silence | The voice starts at Phase. | Manual | High |

## 3. Filters (pp. 5, 16–18)

**Per-part filter (A and B)**

- **Input select:** A, B, AB, or `--` (no input). Each filter apparently offers its own part, AB, or `--` (V1); a part crossing into the other filter goes through both amp envelopes, its own before the filter (the developer, V2); a part no filter selects is silent, and a bypassed filter still takes its select (V4, V5). See [Voice structure and routing](#voice-structure-and-routing) and [voice-architecture.md](../dsp/voice-architecture.md).
- **Type:** Bypass, Lowpass, Bandpass, Highpass. Bypass stops processing altogether.
- **Slope:** 12 dB/oct or 24 dB/oct.
- **Cutoff, Resonance:** resonance goes well past self-oscillation.
- **Drive:** drives the filter's **4 stages, each with nonlinear saturation**.

**Filter Control (shared)**

- **Cutoff and Resonance:** act on both filters at once. The developer: the knob values "are added to the knob values of both filter A and B", "on a logarithmic scale" (below). Decided on 2026-11-21 (task 6) from measured candidates, and built ([filter-control.md](../dsp/filter-control.md)): the knob units add, each control plus its own modulation clamped to 0–10, keytrack after, then one law at 1 octave per unit, 4.5675 Hz × 2^S; the resonances add the same way, k = 0.6 per unit of the sum. Working hypotheses until the demo measures them (F3, F5, F12, F24, F26–F29).
- **Keytrack:** 0–10. At 10, cutoff follows note pitch exactly, so a self-oscillating filter can be played in tune: in its intervals, with the player setting the pitch by the cutoff (the developer; F13, F17–F22).
- **Warm Drive:** on/off. Switches the saturation to a higher-quality mode with more harmonics, at extra CPU cost.

### What is known

The manual gives the structure (four stages, each with a saturator), the four types and two slopes, self-oscillation, Drive, Keytrack, and Warm Drive (pp. 5, 16–18, 30), and the default CCs (p. 31). The rest comes from the specification and home pages, the changelogs of v1.1–v3.050, six of the developer's posts on KVR, and users. The prototypes and measurements are in [filters.md](../dsp/filters.md); the theory is in [filter-theory.md](../dsp/filter-theory.md). M1.3 tasks 1–4 (the core, the responses, cutoff, resonance and drive, Warm Drive) build the hypotheses below as decided on 2026-11-15 (`LadderFilter`): a Newton-solved ZDF transistor ladder with five saturators, tanh with Warm Drive on and a cubic soft clip off, the six responses as tap mixes of the one loop, a true bypass, no resonance compensation, no detune correction, and 1× by default. A measurement that disagrees changes a table row, a saturator, or a mapping, not the model. Keytracking (task 5) is decided and built on 2026-11-15 from five measured models ([keytracking.md](../dsp/keytracking.md); `keytrackOctaves`, `keytrackSource`, `masterTuneSemitones`): linear in octaves from the voice's sounding pitch (key, glide, bend, master tune), reference A-1, the misc source the same quantity, no detune correction, fed at each 32-sample grid point with the pitch at the segment's end. Stability under extreme settings (task 7) is decided and built on 2026-11-15 ([filter-stability.md](../dsp/filter-stability.md)): the Newton solve as before, with a nested bracketing fallback where Newton does not converge (near Nyquist, and at high drive and resonance), so the filter is correct up to the DSP's ceilings; a non-finite input sample taken as 0; the clamp of each control plus its modulation to the knob's range left to the parameter layer; no filter-local aliasing measure (F10 stands). F23–F25 record what the voice can reach and what nothing official covers. The Filter Control's combining law (task 6) has its evidence gathered and its candidates measured on 2026-11-21 ([filter-control.md](../dsp/filter-control.md)), awaiting the decision (F12, F26–F30); the v3 oversampling options are a later round, but their evidence is gathered here too. The DSP takes physical units (the cutoff in Hz, the loop gain k, a drive gain); the knob laws belong to the parameter table (M1.9).

So the official sources fix the structure: four stages, a saturator in each, six responses from them, a true bypass, and two saturator qualities. The developer adds three facts that shape the model: the response at the cutoff is attenuated as an analog ladder's is, the cutoff tops out at half the sample rate, and in 2007 the saturators aliased at high drive and resonance. The "5 independent non-linear saturation functions" fits a transistor-ladder model with a saturator at the loop's input and one per stage. No source gives the cutoff range, the resonance at which oscillation starts, the drive's gain, what Warm Drive's saturator is, or whether the filter is oversampled at the default setting.

**Open questions, settled by measuring the demo (M1.13).** Common setup: Part A only, Osc A1 at A4, Filter A on Input A, Filter B off, the Filter Control's Cutoff and Resonance at 0, where they add nothing if the knob values add (F12; its default is 5, F26, so set it), Keytrack 0, Mix A at unity, the effects off, rendered at 44.1 and 96 kHz. A white-noise or sine-sweep source measures responses (`impulseResponseSpectrum` is not available on a black box, so use Welch averages of output over input with noise, or `measureResponseAt` per tone); a single impulse or note-on starts self-oscillation. Turn on `displayCutoffInHz` in Settings.xml to read the cutoff in Hz. The demo plays a reminder sound about every 60 seconds, so keep renders short or cut around it.

## 4. Amplitude envelopes (p. 17)

One ADSR per part (Amp Env A and B). An attack or release of 0 is allowed and clicks on purpose.

## 5. Mixer (p. 18)

Mix A, Mix B, Main Volume (after the effects), and a stereo VU meter. The output is **not clipped**.

- **Mix A and Mix B** are each part's volume after its filter and amp envelope, before the master effects, on an internal scale of 0 to 15 shown as 0 to 10, modulated additively in internal units (the developer, 2010 and 2016). Mix AB is a modulation destination (p. 22), and the developer's own advice routes velocity, a per-voice source, there. Velocity reaches the level only through a misc slot (V10).
- **Main Volume** sets the output after the master effects (p. 18), on CC 7 (p. 31). Its law, range and default are not given.
- Which Mix acts on a part crossing into the other filter: V3. The level into the filters comes before the mixer, so the mixer can't set where the filters saturate (V8; [voice-architecture.md](../dsp/voice-architecture.md#question-2-the-level-into-the-filter)).
- The mixer's candidates and measurements: [mixer.md](../dsp/mixer.md) (M1.4 task 4, stage 1, 2026-11-22; every recommendation decided by the project owner and built the same day: `mixGain` and Mix in `Voice`, `MainVolume`, `PeakMeter`, `OutputGuard`).

## 6. Modulation (pp. 19–20)

There is **no general mod matrix.** Each source has its own slots:

| Source block | Count | Destinations each | Controls |
|---|---|---|---|
| Mod Envelope | 2 | 2 | ADSR (see [Envelopes](#envelopes)) |
| LFO | 2 | 2 | Wave (10 waveforms in the manual, 11 now; **not named**, see [LFOs](#lfos)), Rate, Gain, Offset (±), Free |
| Misc panel | 2 panels × 2 selectable sources = 4 | 2 | Source selector |

- Each destination has a **bipolar amount** knob (centered means none; double-click resets it), **−10 to +10** (a third-party preset template, and the developer's "−10 for example"). Modulation **adds** amount × source to the knob's value, in the knob's units; for pitch the unit is an octave (the developer). See [Sources, destinations, and amounts](#sources-destinations-and-amounts).
- **Misc sources:** 11 and "none": Velocity, ModWheel, KeyTrack, AmpEnv A, AmpEnv B, ModEnv 1, ModEnv 2, LFO 1, LFO 2, Aftertouch, Step Vlcty (a third-party template; the manual's list agrees). **Confirmed by the demo (M2, settled 2026-11-22):** the same 11 in the template's order, after "-", labelled Velocity, Mod Wheel, KeyTrack, Amp Env A, Amp Env B, Mod Env 1, Mod Env 2, LFO 1, LFO 2, Aftertouch, Step Velocity.
- **Destinations:** 27 and "none" in a grouped popup (Oscillators, Filters, Misc): Volume, Pitch, Phase, Pan, Cutoff and Reso, each for A, B and AB; Mix A/B/AB; LFO 1 and 2 Rate and Gain; the phaser's frequency; the distortion amount (a third-party template). **Confirmed by the demo (M1, settled 2026-11-22):** the same 27 in the template's order, in three columns (12, 6, 9) after "-", and the same menu in every slot. KVR's "24" doesn't match it. No envelope stage (AL8), Main Volume (X7), Detune, Drive or amount is among them.
- **LFO Free:** the LFO is not retriggered on note-on and does **not** follow tempo sync.
- Phase and pitch modulation are evaluated **per voice**, which makes them expensive (p. 30).

### LFOs

The manual gives the outline (pp. 12, 19–20). There are two LFOs, and they "offer 10 different waveforms", which it does not name. **Rate** "sets the oscillator frequency" and **Gain** "changes the amplitude". **Offset** "can be used to add a positive or negative constant value to output of the LFO. If Offset is set to 0, the output wave will be centered around 0." With **Free** pressed, "the LFO will run freely and will not be retriggered when a new note is played, nor will it sync to the host tempo". With Sync off, rates show "in seconds or Hertz" (p. 12). The default CC map gives LFO 1 Rate, Gain, and Offset CC 84–86 and LFO 2 CC 87–89; Wave and Free have no CC (p. 32). Everything past that comes from release notes, the developer's forum posts, and users. The prototypes and measurements are in [lfos.md](../dsp/lfos.md). M1.2 builds the hypotheses below as decided on 2026-11-14 (`Lfo`). The DSP takes the rate in Hz, gain in [0, 1], and offset in [−1, 1]; the knob laws belong to the parameter table (M1.9), so a measurement that disagrees changes a mapping or a row, not DSP code.

## 7. Voicing and keyboard (pp. 11–12, 29)

- **Polyphony:** 0–16 notes. The Voices readout shows active voices and the maximum, where the maximum is the sum of the oscillator voice counts × polyphony. Allocation, stealing, freeing, and the readout: [Voice allocation](#voice-allocation) (P1–P7).
- **Pitch bend,** with **Bend Range** "in half notes" (p. 29), up to 24 since v1.1. The wheel is MIDI-learnable since v3.072.
- **Mod wheel** is available as a mod source.
- **Mono Legato:** forces mono and does not retrigger envelopes, so pitch and velocity slide between notes.
- **Portamento:** time knob (default CC 5) plus a mode switch. In **Normal**, it slides only when notes overlap. In **Slide**, it always slides. It works in poly as well as mono (the product description).
- **Hold pedal:** CC 64.
- Mono Legato, portamento, the bend, and the pedal in detail: [Mono Legato, portamento, pitch bend, and the hold pedal](#mono-legato-portamento-pitch-bend-and-the-hold-pedal) (K1–K19).
- **Per voice:** "almost a whole copy of the audio path is made (except for the master effects)" for every note (p. 30): the four oscillators, both filters (stereo), and both amp envelopes, with routing as in [Voice structure and routing](#voice-structure-and-routing). Parts not in use are switched off (p. 6; V13). Measured on our prototype (M1.4 stage 1): 361 ns per sample per voice at the init patch, 691 at 4 oscillators × 8 unison into both filters on AB ([voice-architecture.md](../dsp/voice-architecture.md#cpu)). What is skipped, and Solo: [Part solo and skipping unused parts](#part-solo-and-skipping-unused-parts) (M1.4 task 5).

## 8. Tempo sync (pp. 12, 20)

A global **Sync** switch shows LFO rates, delay times, and similar values as note lengths (for example 1/4 and 1/8, plus **T** for triplet and **D** for dotted) locked to host tempo. When it is off, those values are shown in seconds or Hz.

The manual gives one paragraph (p. 12) and the Free button's exception (p. 20). The rest comes from the specification page, two changelog lines, three developer posts on KVR, and users. The prototypes and measurements are in [tempo-sync.md](../dsp/tempo-sync.md). M1.2 builds the hypotheses below as decided on 2026-11-14: rate only, the phase from the note-on and never the song position, exact note values (`NoteValue`, `syncNoteValues`, `notePhaseIncrement()`), and the host's last valid tempo (`HostTempo`). A measurement that disagrees changes the list, a mapping, or the fallback, not the model. In the DSP, a note value is an exact fraction of a whole note, and the inputs are plain values: the tempo in quarter notes per minute, plus the host's position in quarter notes and whether it plays. Reading the host is M1.9's job, and the value list and knob steps belong to the parameter table (M1.9).

## 9. Arpeggiator (pp. 5, 20–22)

- **Modes (10):** Up, Down, Up/Down, Up/Down 2, Down/Up, Down/Up 2, Random, Ordered (the order the keys were pressed), Step Seq (one note at a time), and Step Chord. The manual names seven and counts 10. A third-party preset template lists all 10, in this order (AR1).
- **Time** sets the step rate (synced 1/1 to 1/64; ms with Sync off). **Gate** sets the note's length as a fraction of a step (0–100%). **Wrap** restarts the sequence after N notes (0–16). **Octave** sets the range in octaves (1–4). **Swing** (v3.050). An on/off checkbox.
- **Step sequencer, 16 steps:** each step has a **Transpose** (−24 to +24 semitones, used in the Step modes only), a **Velocity** (0–127; `-` means the note isn't played), and a **Hold** flag that extends the note into the next step, for slides. Whether the steps are shown in pages is unconfirmed (AR14). The panel has C and P buttons for copy and paste, as every effect panel does (p. 20).
- **Velocity mode:** Key, Hold (the last key's velocity), Step, Step+Key, or Step+Hold.
- Outputs **Step Velocity** as a modulation source, which is useful for gating. It runs whether or not the arpeggiator is on (M23).

## 11. Presets and banks (pp. 11–13)

- A bank holds 512 presets in 4 sub-banks of 128. MIDI program change reaches only the first 128.
- Programs can be changed from the host, with the prev/next arrows, from a popup list, or by MIDI program change.
- Load and save single presets and whole banks (Sylenth1 uses `.fxp` and `.fxb`; ours will use our own format).
- Menu actions: Copy, Paste, Insert, Delete, **Clear** (initialize), **Randomize**, **Reset** (undo all edits to the preset), and rename.

## 12. MIDI control (pp. 10–11, 31–32)

- Every main knob has a **default CC** assignment (the table is on pp. 31–32, CC 1–127, including CC 123 All Notes Off). *M1.5 task 5 (2026-11-23): the table has no modulation control: no amount, no source or destination selector, and no Mod Envelope knob ([Global destinations, parameters and CCs](#global-destinations-parameters-and-ccs)).*
- **MIDI Learn and Forget** are available from each knob's right-click menu. Learned assignments **persist across sessions** (global, not stored per preset).

## 13. UI interaction (p. 10)

These are not DSP features, but they are expected UI behavior:

- Drag vertically to change a value. Shift-drag gives fine control. Alt switches to rotary drag.
- Double-click or Ctrl-click resets a knob to its center or default value.
- Clicking a knob shows its value on the LCD without changing it.

## 14. Performance notes from the manual (p. 30)

- The voice path (oscillators, filters, envelopes) is duplicated for every note, so its cost grows with polyphony.
- One oscillator with 4 voices is cheaper than 4 oscillators with 1 voice each, which suggests unison is vectorized inside each oscillator.
- Bypassed filters and disabled effects cost nothing.
- Sylenth1 uses SSE. These notes are inputs to Part 3.
