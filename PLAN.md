# Brutalis plan

The working plan for the project. [CLAUDE.md](CLAUDE.md) holds the rules: stack, architecture, and conventions. This file holds the **order of work and its status**. The feature target is [docs/reference/sylenth1-features.md](docs/reference/sylenth1-features.md).

## How to use this file

- Status markers: `[ ]` not started · `[~]` in progress · `[x]` done · `[-]` dropped (say why).
- Work milestones in order unless the dependencies listed say otherwise.
- Every task meets the **Definition of done** below before it is ticked.
- Record each decision under **Decisions log** with the date. Move it out of **Open decisions** once it is made.
- Keep this file current. Update it in the same commit as the work.

## Definition of done (every task)

1. A Catch2 test was written first and failed, then the code made it pass (TDD).
   Before committing, `tools/check.sh` passes locally (macOS).
2. Builds without warnings and all tests pass on macOS, Linux, and Windows. *macOS is checked locally before every commit. Linux and Windows are checked by Version CI on every major or minor version (`vX.Y.0`). A task counts as done once it passes macOS. Linux or Windows failures found in a version run must be fixed before that version ships.*
3. Code is formatted with clang-format, and clang-tidy reports nothing.
4. Audio-thread code is real-time safe. `libs/dsp` code meets the portability rules in CLAUDE.md (no JUCE, no allocation after prepare, and so on).
5. Part 4 docs are written or updated for the technique (see the doc column of each milestone).
6. PLAN.md is updated.

### M1.5 Modulation system (§6)

**How it runs** (planned 2026-11-22), as M1.4 did: each task is **stage 1** (gather the evidence into the inventory, prototype the candidates in `tests/` on the real classes, measure them, and write the doc's recommendations), then **the project owner's decision** (Decisions log), then **stage 2** (build what was decided, test first, bit for bit the stage-1 prototype at host blocks 1/37/4096, with no allocation). Tasks run in order: task 1 settles the facts that every later task needs, and task 2 the model that tasks 3–5 build on.

**Invariants every task keeps** (from M1.0–M1.4):
- The output doesn't depend on the host's block size. Anything evaluated at control rate runs on the voice's own 32-sample grid, counted from its note-on. Global ramps are read at absolute sample times, as `PitchBend` is.
- **A patch with no routes renders exactly as today, to the bit.** An empty slot, or an amount of 0, adds an exact 0 and costs no measurable CPU.
- The skip test never skips audio. Each route to a factor the test reads adds that route's bound.
- `libs/dsp` rules: no allocation after `prepare()`, no RTTI or exceptions, no JUCE.

### M1.6 Arpeggiator and step sequencer (§9)

**How it runs** (planned 2026-11-23), as M1.4 and M1.5 did: each task is **stage 1** (gather the evidence into the inventory, prototype the candidates in `tests/` on the real classes, measure them, and write the doc's recommendations), then **the project owner's decision** (Decisions log), then **stage 2** (build what was decided, test first, bit for bit the stage-1 prototype at host blocks 1/37/4096, with no allocation). Tasks run in order: task 1 settles the facts every later task needs, task 2 the pattern, and task 3 the clock that tasks 4 and 5 build on. Task 1 is research only, so it runs alongside M1.5 task 5. Every later task waits for M1.5 to close.

**Invariants every task keeps** (from M1.2–M1.5):
- **With the arpeggiator off and no route reading Step Velocity, the engine renders exactly as today, to the bit**, at no measurable cost.
- The output doesn't depend on the host's block size. Every step, gate end and swung onset falls on a sample computed exactly from the sequence's start (M1.2's `NoteValue`, ⌈k · num / den⌉ or a 64-bit phase), never by adding rounded lengths. Each event splits the block at its sample.
- Random draws come from the seedable generator ([white-noise.md](docs/dsp/white-noise.md)), so the same MIDI renders the same audio.
- `libs/dsp` rules: a fixed-capacity held-note set (no allocation after `prepare()`), no RTTI or exceptions, no JUCE. The pattern and the clock are separate plain-C++ pieces, and the pattern can be driven by an external clock and reset (R1's Rack module). The modes sit behind one interface, so Phase 2 can add modes (CLAUDE.md).

### M1.7 Master effects (§10)
Each effect is a standalone, reusable `libs/dsp` processor. Add them to the fixed chain with bypass switches.
- *Requirement from M1.5 task 2 (decided 2026-11-22, [modulation.md](docs/dsp/modulation.md#the-decision)): the global destinations (PhsrFreq, DistAmnt) take their modulation on the absolute 32-sample grid, ramped, and read each per-voice source's **global copy**: an envelope gated by the first key down and released by the last, the last note-on's velocity, a free LFO's global instance, the last note's keytrack. Never the newest voice (jumps at note-ons) or a sum over voices (grows with the chord).*
- *Requirement from M1.5 task 3 (decided 2026-11-22, [modulation-sources.md](docs/dsp/modulation-sources.md#the-decision)): a free LFO's global instance is the same object the voices copy (one per LFO, in the engine). The other global copies (an envelope gated by the first key down and the last key up, the last velocity, the last keytrack) are new engine objects, run only while a global destination reads them, as the voices' sources are.* *Built 2026-11-23 (task 3): the global instances are the engine's `std::array<Lfo, 2>` that `modulation::SourceContext::freeLfos` points to.*
- *Requirement from M1.5 task 5 (decided and built 2026-11-23, [modulation-hand-offs.md](docs/dsp/modulation-hand-offs.md#the-decision)): **the engine compiles the global routes**: a `modulation::RouteCompiler{Scope::global}` over the same `Patch` the voices read (`compile(slots, Scope::global)`; the voices compile only `Scope::voice`, so they ignore these routes entirely). It sums them on the absolute 32-sample grid from the sources' global copies (above), **crossfades any change of them over 10 ms** as the voices do (`routeCrossfadeSegments()`, started only when `sameRoutes()` says the routes changed), and **clamps each effect knob plus its modulation to the knob's range before its law** (the registry's `knob10` until the effects' knobs give their own ranges; Phaser CenterFreq and Distortion Amount are the targets, `Target::phaserFrequency` and `Target::distortionAmount`, part 0). A global destination with no route costs nothing, and runs no global copy.*
- [ ] Distortion: Overdrive, Foldback, Clip, Decimate, Bitcrush. Amount, dry/wet. 4× oversampling.
- [ ] Phaser: 6 stages, center frequency, spread, LR offset, width, internal LFO, feedback, dry/wet. 2× oversampling.
- [ ] Chorus/Flanger: delay, rate, depth, feedback, dual mode (4 lines in quadrature), width, dry/wet. 2× oversampling.
- [ ] EQ: bass and treble shelves with frequency controls and **automatic volume normalization**.
- [ ] Reverb: size, damp, predelay, width, dry/wet.
- [ ] Delay: L/R times (sync), feedback, ping-pong with spread, width, low and high cut, **smear**, dry/wet.
- [ ] Compressor: ratio 1:1 to 100:1, threshold 0 to −30 dB, attack, release. Stereo-linked.
- [ ] Chain: Distortion → Phaser → Chorus → EQ → Reverb → Delay → Compressor. Disabled effects cost nothing.
